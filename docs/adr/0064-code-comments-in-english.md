# 0064. コード内のコメント / docstring を英語に統一し、ユーザーが読む文字列は日本語のまま残す

- Status: Accepted
- Date: 2026-07-31
- Related: [ADR-0061](0061-remote-control-as-cli.md)（click コマンドの docstring が `vsctl --help` 本文そのものになった経緯）

## Context

`vspeech/` / `cli/` / `scripts/` / `tests/` のコメントと docstring は、日本語と英語が**ファイル単位でも行単位でも混在**していた。書いた時期と気分で決まっていただけで、境界に理由が無い。同じ関数の中で「なぜこの定数か」の説明が日本語、その 3 行下の TODO が英語、ということが起きる。

一方で、**コード内の文字列すべてが同じ性質ではない**。ログ・例外メッセージ・`config.py` の `description=`・`vsctl --help` の本文は、コードを読まない運用者（日本語話者）が読む出力で、コメントとは読者が違う。ここを一緒くたに英語化すると「コメントの言語統一」ではなく「製品の表示言語変更」になる。

変換量は実測で 84 ファイル / 約 2,800 行。一度に入れると差分が読み切れない。

## Decision

**`#` コメントと docstring は英語で書く。ユーザーが読む文字列は日本語のまま残す。**

日本語のまま残すもの（＝読者が「コードを読む人」ではないもの）:

- ログメッセージ、例外 / `SystemExit` のメッセージ
- `config.py` の `description=`
- argparse の `help=` / `description=` / `epilog=`
- click の `help=`、および **click コマンドの docstring**（docstring だが、実体は `vsctl --help` の本文）
- 日本語のテストフィクスチャと、日本語の文言そのものを検証する assertion

**残った日本語コメントは、再スイープでまとめて潰さない。そのファイルを別件で編集する機会が来たときに、そのファイル分だけ英語化する。**

散文ドキュメント（ADR / spec / plan / `README.md`）は日本語のまま。本 ADR の対象はコード内テキストだけで、ドキュメントの言語には触れない。

## Alternatives rejected

- **日本語に統一する** — 読者（本人 + コーディングエージェント）はどちらも読めるので可読性では決まらない。決め手は識別子・型名・ライブラリの語彙・ADR 番号参照が既に英語で、コメントが英語だと地の文と用語が一致すること。日本語だと「`following_events` を辿る」のような助詞接続が毎行入る。
- **ユーザー可視文字列も含めて全部英語にする** — 目的が別の変更。`vsctl --help` や preflight のエラーが日本語で読めることには実利があり（[ADR-0038](0038-worker-config-preflight-fail-loud.md) の fail-loud は「読んで直せる」ことが前提）、日本語文言を検証しているテストも巻き込んで壊れる。
- **残り全部を変換し切ってから main に入れる** — 差分が大きいほどレビューが形骸化する。コメントのみの変更であることは機械的に示せる（下記）ので、分割して入れるコストが低い。混在期間中に迷う場面は「新しく書くとき」だけで、そこは本 ADR が答えを固定している。
- **lint で機械的に強制する（コメント内の非 ASCII を禁止）** — ruff に該当ルールが無く自前 hook になる。しかも上の例外リストは「コメントではない場所」の話なのでルール側では表現できず、結局 per-file の除外リストを保守することになる。残存量が有限（下記 3 ファイル）である以上、機構が残るだけ。

## Consequences

- 新規コードでコメントの言語を都度決めなくてよくなった。
- コメント / docstring だけの変更であることは、**docstring を剥がした AST を HEAD と突き合わせれば機械的に証明できる**（コメントはそもそも AST に現れない）。今回の 84 ファイルはこれで検証した。以後の per-file 英語化にも同じ手が使える。
- 未変換のまま残っているのは `tests/test_obs_ws.py` / `tests/test_vad_gate.py` / `tests/test_log_throttle.py` の 3 ファイル。編集する機会に英語化する。
- 「日本語のまま残す」側は消極的な放置ではなく決定なので、あとから機械的に英語化してはいけない。
