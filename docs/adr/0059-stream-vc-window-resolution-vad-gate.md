# 0059. ストリーミング VC の VAD ゲートを 32ms 窓粒度 + emit 遅延補正にする

- Status: Proposed (refines [0053](0053-streaming-vc-fixed-block-crossfade.md))
- Date: 2026-07-25
- Related: [0019](0019-vc-silero-vad-gate.md), [0037](0037-transcription-vad-skip-gate.md), [0053](0053-streaming-vc-fixed-block-crossfade.md)（この ADR がゲート部分を refine する）, [0057](0057-streaming-input-envelope-rolling-ema.md)

## Context

実機で「発話の**最初の音節そのものが息っぽくなる**」という症状が出た。実録音(12s・発話 3 回)を実 config・実モデルで通して切り分けた。

**症状の本体は、発声直前の微小入力が音として合成されて出ていること。** 同じ音声・同じモデルで発声前 80ms の出力を測ると **streaming 0.0449 / batch(`change_voice`) 0.000308 = +43dB**(入力自体は RMS 0.002)。バッチ経路は同じ区間をほぼ無音に描く。

### 機序として確定したこと

- **解析窓の中身に依存する**。左文脈の無音量を振ると語頭ブロックの倍音性が単調に落ちる(窓内無音 0ms→0.94 / 500ms→0.37 / 1000ms→0.17)一方、**定常ブロックは無音量に一切反応しない**(0.93 固定) — 「語頭だけ」という症状と一致する。左文脈の**中身だけ**を dither(RMS 1e-3)や音声に差し替えると、それと重ならない発声前区間の出力が 31dB 下がる。
- **f0 経路ではない**。発声前フレームに擬似的な有声 f0 が出ている(batch 窓では無声の区間に 262Hz)ので当初これを疑ったが、**f0 を batch 窓由来のものへ差し替えても(+45.3dB)、発声前フレームを無声に強制しても(+44.4dB)、症状は消えない**(素のまま +43.4dB)。NSF ソースの問題ではない。
- **content encoder が同じ音を別物として符号化している**。同じ発声前音声に対する HuBERT 特徴を左文脈だけ変えて比べると、**向きが変わる**(silence 基準の cos: dither 0.575 / speech 0.110)。一方**大きさはほぼ不変**(0.294 → 0.290 / 0.362)。

### 機序として確定していないこと

窓のどの性質が効いているかは**切り分けていない**。候補は (a) 特徴抽出器 第1層の GroupNorm(ONNX 上は `InstanceNormalization`、窓全体の時間軸統計で正規化する)と (b) transformer の自己注意(窓全体を見る)。上の実験はどちらも同時に動かすので判別できない。**「窓正規化が微小入力を音声レベルまで持ち上げる」という説明は採らない**: それはチャネルごとに時間軸へ一様なアフィンをかけるだけで窓内の相対レベルを変えられず、実測でも特徴の大きさはほぼ動いていない。この ADR の決定はこの帰属に依存しない。

### なぜ batch では聞こえず streaming で聞こえるか

モデル側は動かせない。可聴にしていたのは**ゲートの粒度と位相**だった。

- **粒度**: [0053](0053-streaming-vc-fixed-block-crossfade.md) のゲートはブロック粒度(160ms)で窓確率の **max** を採る。語頭ブロックでは 1 窓(実測 p=0.868)のせいでブロック全体が full gain で開き、その手前の 4 窓(0.030/0.222/0.140/0.082)ごと通していた。発話系 `[vc]`([0019](0019-vc-silero-vad-gate.md))は `speech_gate_mask` / `apply_vad_gate` で 32ms 窓ごとにマスクするので同じ区間を落とせる。
- **位相**: emit の内容は入力ブロックより手前から始まる(crossfade + SOLA + HuBERT 受容野の末尾切り詰め)。batch 出力との相互相関で実測 **51.8ms**。ブロック粒度ゲートはこれを補正しておらず、判定が 52ms ずれた音声に当たっていた。
- **VAD の入力**: `speech_probs` は呼び出しごとに Silero の再帰状態と 64 サンプル context をゼロにする。発話全体を 1 回で渡す発話系ではそれで正しいが、streaming は 160ms ブロックごとに呼ぶので **RNN が毎秒 6.25 回コールドスタート**していた。実測(同じ録音・同じモデル): 明確な有声窓(入力 RMS>0.05)34 個の確率が、状態を継続すれば min 0.969 / mean 0.996 なのに、ブロック毎リセットでは min 0.024 / mean 0.411 で **15 個が 0.3 を割る**。ブロック粒度の max 判定はこれを隠していたが、窓粒度は 1 窓ずつ直接使うので隠せない。

## Decision

streaming の VAD ゲートを **32ms 窓粒度のマスク + emit 遅延補正**にする(`vspeech/stream_vc/gate.py`)。

- **判定も適用も 32ms 窓ごと**。`window_gains(probs)` が窓ごとのゲインを返し、`apply()` がそれを emit のサンプル格子へ写す。ブロック粒度の max 判定(`speech_from_probs` / `update` / `ramp`)は廃止する。確率は既にブロックごとに 5 窓ぶん計算しているので**追加の推論コストはゼロ**。
- **Silero の再帰状態をブロックをまたいで持ち越す**。`vspeech/lib/vad.py` に `VadCarry` を足し、`speech_probs(session, audio, carry=None)` の任意引数で受ける(既定 None = 従来どおり毎回コールド = 発話系は無改変)。ゲートが carry を所有する。carry 付きのブロック分割は信号を丸ごと 1 回渡すのと**同じ確率**を返す(ブロック長が窓長 512 の倍数のとき。既定 160ms = 5 窓は該当する。倍数でないと末尾窓のゼロパディングが carry に入って一致しない)。
- **`reset()` は hangover とマスクだけ戻し、VAD の再帰状態は捨てない**。実時間が飛んだのだから新品にするのが素直に見えるが、実測(実録音・全ブロック境界で reset を模擬)ではコストが非対称だった: 新品にすると直後 1 ブロック目で真値の発話窓の **42%**、2 ブロック目でも 16% を落とす(持ち越せば 0%)。resume 直後に発話が続いていると語頭が欠ける = この ADR が消そうとしているのと同種の症状になる。残す側のコストは「飛ぶ前の音で育った状態が最初の 1〜2 窓を余計に開けるかもしれない」程度で、hangover 予算とマスクは reset で閉じている。
- **hangover は後方 dilation としてのみ効かせる**。`vad_hangover_ms` の意味は「最後に speech と判定した窓からゲートを開けたまま保つ時間」で、ブロック境界をまたいで持ち越す。**前方へは広げない** — 前方へ広げると語頭直前のブレスをそのまま開けてしまう(実録音へマスク単体をかけた実測: 前方 0ms で -26dB のところ、32ms 足すと -9dB まで後退する)。
- **emit 遅延を補正して重ねる**。`StreamingVc` が `emit_delay_samples`(= `context_len` の出力サンプル換算 − 読み出し開始位置)を公開し、ゲートはその分だけマスクをずらす。**この遅延は SOLA の lag を含めない公称位置から導く**: lag は tick ごとに ±`sola_search_ms` 動くので、それを時刻軸に載せるとマスクの時刻軸が tick ごとに再アンカーされ、継ぎ目でゲインが跳ぶ(構造上の上限 2*out_sola/窓長 = 0.31 = クリック)。残る内容ずれは高々 5ms でマスクの分解能 32ms より十分小さい。
- **ゲインは窓中心のあいだを線形補間する**(発話系 `apply_vad_gate` と同じ)。ブロック境界は前ブロックのマスクを左へ連結してから補間する。**前ブロックの原点は emit 長(hop)ぶん手前**であって「窓数 × 窓長」ではない: `speech_probs` は `ceil(block_len/512)` 窓へゼロパディングするので、`block_len` が 512 の倍数でない設定(config が挙げる `block_ms=80` など)では窓の総長がブロック長を超え、窓グリッド基準だとマスク全体が早まる(80ms 設定で 16ms)。
- **初期状態と reset 直後は「閉」**。窓単位なら speech の窓がそのまま開くので、[0053](0053-streaming-vc-fixed-block-crossfade.md) が「開いた状態から始める」理由にしていた「全ブロック ramp が語頭を舐める」問題は起きない。emit の頭(遅延ぶん)も閉から立ち上げる — そこにあるのは pause 前の音、または zeros 文脈から描かれた音だから。
- **全窓 1.0 かつ直前も 1.0 なら恒等の高速路**。既定 off / 常時 speech の出力は無ゲート時とビット単位で同一(起動直後・reset 直後の 1 ブロックだけは閉から開くので例外)。

### 実測(実録音・実モデル・実 config)

| 区間 | batch(基準) | 修正前 | 修正後 |
|---|---|---|---|
| utt1 ブレス | 0.00040 | 0.04166 | **0.00239 (-24.8dB)** |
| utt3 ブレス | 0.00164 | 0.01745 | **0.00791 (-6.9dB)** |
| utt1 語頭 | 0.14276 | 0.21606 | 0.21203 (-0.2dB) |
| utt3 語頭 | 0.16824 | 0.21320 | 0.21737 (+0.2dB) |
| utt1 定常 | 0.15895 | 0.13160 | 0.15242 (+1.3dB) |
| 無音 | 0.00013 | 0.00000 | 0.00000 |

本物の語頭・定常は保持。副次的に、ブロック粒度ゲートが語間を丸ごと落としていた欠陥(実測 0.13942 → 0.08389)も直る。emit 遅延は全 tick で 50.0ms 一定、**継ぎ目のゲイン段差は 74 箇所すべてで 0.0000**(定数信号へ実マスクを適用して測定)。

残差は batch 比 +15dB(utt1、声より 39dB 下)/ +14dB(utt3、声より 26dB 下)。マスクの立ち上がりが窓中心間 32ms かけて渡るぶん、ブレス末尾が ramp 帯に残る。可聴なら次の手は「開放だけ短い窓で立ち上げる非対称補間」または下記 dither。

## Alternatives rejected

- **HuBERT 解析窓へ dither(微小雑音)を足す** — 窓の統計を安定させる方向で、単体で +43dB → **+12dB**(実測)。だが全ブロックの変換入力に雑音を加算することになり、最適レベルがマイクレベル依存の調整パラメタになる。ゲート側の修正は変換出力に手を触れず同等以上の効果があるので、まずこちらを採る。残差が可聴なら再検討の余地は残す。
- **look-ahead(窓の右へ後続音声を足す)** — 実測で語頭の倍音性は改善しなかった(左文脈 500ms 固定で la=0/40/80/160ms のいずれも harm 0.25〜0.44)。右文脈不足ではないので、遅延を払う価値がない。
- **語頭で context を短くする** — 無音の割合を下げる方向だが、[0053](0053-streaming-vc-fixed-block-crossfade.md) の実機耳確認で context 500ms 未満は seam がガタつくと確定している。ブロックごとに context 長を変えると入力 shape が変わり、固定 shape・warmup 1 回の前提も壊れる。
- **バッチ側 `speech_gate_mask` をそのまま使う(前後対称 dilation)** — `vad_speech_pad_ms` 相当を前方にも効かせると語頭直前のブレスが開く。実録音の生 streaming 出力へマスク単体をかけて測ると、前方 0ms の -26dB(0.0463 → 0.00226)に対し、前方 32ms では -9dB(0.0164)まで後退した。前方 0 が要件。
- **遅延補正だけ入れてブロック粒度は据え置き** — 同じ実測でブレスは 0.0463 → 0.0187(-8dB)にしかならない。粒度がボトルネックなので単独では足りない。
- **ブロック粒度の max 判定を mean/ratio に替える** — 発話系 `should_skip_vc` の ratio と同型にする案。ブロック内のどこが非音声かという情報を捨てている点は max と変わらず、語頭ブロック(1/5 窓が speech)は丸ごと落ちるか丸ごと開くかの二択になる。
- **VAD の状態持ち越しを `speech_probs` の既定挙動にする** — 発話系(vc / transcription)は発話全体を 1 回で渡すので、チャンク境界が「見たい音の始まり」であり毎回コールドで始めるのが正しい。既定を変えると発話系の判定が静かに変わる。任意引数にして streaming だけが持ち越す。
- **ドロップしたブロックのマスクを次ブロックへ持ち越す(`_prev_gains` を必ず進める)** — レビューで「drop 時にマスクが 1 ブロック古くなる」と指摘されたが、実測で**据え置きが正しい**と確認した。`process_block` は infer で raise すると `self._context` を更新しないので、次の成功ブロックの emit 先頭は drop したブロックではなく最後に成功したブロックの尾の再描画になる(f0 マーカ付き入力で block 4 を drop → 次 emit 先頭 45ms の f0 は 522Hz = block 3 の期待値 530Hz、drop した block 4 の 699Hz ではない)。二つの staleness が相殺する。進めると drop したブロックのマスクを別の音に当てることになる。

## Consequences

語頭のブレスが可聴域から外れ、語間の欠落も直る。追加の推論コストは無い(窓確率は既に計算済み)。

- `vad_hangover_ms` は「ブロック単位の予算」から「窓単位の後方 dilation」へ意味が変わる。単位(ms)と趣旨は同じなので既存設定はそのまま使えるが、内部では 32ms 窓数へ丸められる(300ms → 9 窓 = 288ms)。
- **`vad_threshold` の推奨は変えない**。窓粒度化で threshold がシビアになるという当初の懸念は、VAD の状態を持ち越したら消えた: 実録音で threshold 0.3 / 0.5 / 0.7 は開く窓数が 84 / 83 / 82 とほぼ同じで、いずれもブレス窓を 1 つも開けない(0.2 まで下げると 3 つ開く = 悪化する)。既定 0.5 のままでよい。**下げる必要は無い**。
- `stream_vc_vad_gated` telemetry の意味が「ブロックの目標ゲインが 1 でない」から「1 窓でも減衰した」に変わる。
- 起動直後・reset 直後の 1 ブロックは、常時 speech でも無ゲート時とビット単位一致しない(emit の頭が閉から立ち上がる)。2 ブロック目以降は一致する。
- content encoder 側の増幅(+43dB)自体は残っており、ゲートで可聴域外へ落としているだけである。ゲートを off にすると語頭のブレスはそのまま出る。
