# 0070. f0 の中央値フィルタを有声区間単位で全抽出器に掛ける（本家 RVC の filter_radius 相当）

- Status: Accepted
- Date: 2026-08-10
- Related: [spec](../superpowers/specs/2026-08-10-f0-median-filter-design.md), [ADR-0030](0030-pyworld-lazy-default-rmvpe.md), [ADR-0049](0049-fcpe-baked-waveform-onnx-f0-extractor.md), [ADR-0053](0053-streaming-vc-fixed-block-crossfade.md)

## Context

f0 の平滑化は harvest 経路にしか無かった。本家 RVC も `filter_radius` を harvest にしか適用
していないが、こちらは既定の抽出器が rmvpe（[ADR-0030](0030-pyworld-lazy-default-rmvpe.md)）
で、streaming の既定は fcpe（[ADR-0049](0049-fcpe-baked-waveform-onnx-f0-extractor.md)）で
ある。つまり実際に使われる 2 経路がどちらも生の f0 を NSF へ渡していた。

f0 抽出はブロック独立で、ブロック間の連続性を拘束する仕組みも無い。1 フレームだけのオクターブ
誤りが打ち消されずに合成へ届き、短い異音として出力に乗る。単発の外れ値は中央値フィルタが最も
素直に消せる種類の誤りである。

素直な適用を阻む力が 2 つある。

第一に、無声フレームは 0 で表現されている。f0 列全体へ中央値フィルタを掛けると 0 が窓に混ざり、
有声区間の端が 0 側へ引かれる。長さ 3 の窓なら有声先頭は `median(0, a, b) = min(a, b)` になる。
有声の立ち上がりと切れ際が鈍るこの副作用は、消したい異音より耳につきやすい。

第二に、streaming 経路には先読みの余裕がほとんど無い（[ADR-0053](0053-streaming-vc-fixed-block-crossfade.md)）。
`window = 160` @16kHz なので f0 は 1 フレーム 10ms。既定構成では解析列が
`[左文脈 500ms | ブロック 160ms]` の 660ms ≒ 66 フレームで、emit は入力ブロック相対
`[-50, +110]ms` を覆う。**emit 終端の後ろに残る右文脈は約 30ms = 3 フレーム**しかない。
`scipy.signal.medfilt` の既定であるゼロ詰めをこの末端に適用すると `median(a, b, 0) = min(a, b)`
となり、出力へ渡る最新フレームを必ず下方向へ壊す。

## Decision

抽出器の分岐直後、`pitch_extract()` の中で **有声区間ごとの中央値フィルタ**を全抽出器へ一様に
掛ける。`f0 > 0` の極大連続区間をそれぞれ独立に畳み、無声フレームは窓に入れず値も変えない。
区間の端は **edge 複製**で埋める（ゼロ詰めにしない）。強さは `RvcConfig.f0_filter_radius`
（既定 1、`0..7`、窓長 `2r+1`）で与える。`f0` は `f0_up_key` の正のスカラー倍と可換なので、
適用位置は倍率の前でも後でも結果は同じであり、可読性のために抽出直後へ置く。

同時に `pitch_extract_harvest` の `signal.medfilt(f0, 3)` を削除し、経路を 1 本にする。既定
`radius = 1` は窓長 3 で harvest の従来の強さと一致するため、harvest の既定挙動は「有声区間の
端にゼロが混ざらなくなる」分だけ変わる（改善方向）。

`f0_filter_radius` は `pitch_extract()` の**必須引数**とし、シグネチャ側に既定値を置かない。
既定値を config と関数の両方に書くと片方だけ動いて静かにズレるため、既定の出所を
`RvcConfig` のフィールド 1 箇所に閉じる。

この決定はフィルタに**自前の先読みを一切要求させない**。edge 複製により配列末尾は恒等になる
が、上記のとおり emit 終端の後ろには既に約 3 フレームの右文脈があるため、`radius <= 3` では
出力へ渡るフレームがすべて本物の両側窓で畳まれる。

## Alternatives rejected

- **本家 RVC どおりの素の `signal.medfilt(f0, 3)`（無声 0 を含めて一様に適用）** — 0 が窓に
  混ざり、有声区間の先頭が `min` 方向へ引かれる。有声境界が鈍る副作用は、除去したい単発異音
  より耳につく。本家が harvest にしか適用しておらず、かつ harvest が実質使われていないため、
  この欠点が上流で表面化していないだけである。
- **端のゼロ詰め（`scipy.signal.medfilt` の既定）** — 配列末尾＝emit へ渡る側の最新フレームを
  必ず下方向へ壊す。edge 複製なら同じ位置が恒等になり、劣化ではなく単なる無処理に落ちる。
- **フィルタ自身が先読み（r フレームの遅延）を要求する** — 推論あたり約 40ms の固定フロアに
  対して +10ms を払う価値が無い。並行して進む「右文脈を設定可能にする」作業は先読みそのものを
  否定していない。ここで否定するのは**中央値フィルタが自前の先読みを持ち込むこと**だけである。
- **ブロックをまたいで f0 の状態を持ち越す（連続性拘束）** — 解析列が既に約 50 フレームの左
  文脈を含んでおり、区間内フィルタに必要な左文脈は配列内で足りている。状態を持てば純関数性を
  失い、warmup / pause / デバイス再接続でのリセット漏れという新しい失敗モードを買うことになる。
- **オクターブジャンプの能動的補正（running median への倍・半引き戻し）** — 単発誤りより強い
  介入で、誤ったオクターブへロックし得る。観測されている症状は単発誤りなので窓長 3 で足りる。
  必要になってから独立に評価する。
- **既定 `radius = 0`（オプトイン）** — 出音を 1 サンプルも変えずに landing できるが、harvest の
  `medfilt` を残して分岐を 2 本にするか、harvest も既定 OFF にして本家と乖離するかの二択を
  強いられる。そもそも既定の音を良くすることが目的である。
- **抽出器ごとに強さを分ける（rmvpe と fcpe で別の既定）** — 窓長 3 の中央値は「両隣より外れた
  1 フレーム」しか動かさない実質透過の処理で、抽出器ごとに分ける根拠が無い。ノブが増えるだけ。

## Consequences

- 既定の出音が変わる。ただし実測 (RTX 5060 Ti / rmvpe / `Uyu-V4S-16-dynamo_simple.onnx`) では
  変化は小さい。ゴールデンの入力である 220Hz サイン 1 秒で、`radius` 0 と 1 の f0 差は
  **最大 1 cent** (有声 100 フレーム中 55 が動くが、いずれも rmvpe のフレーム間ジッタの
  平滑化)、`f0_coarse` のビン反転は **0**、波形は相関 0.999932 / SNR 38.7dB。バッチ経路の
  数値ゴールデン (`tests/assets/rvc_golden/`、**gitignore 済みのローカル資産で commit されない**)
  は `CORR_MIN = 0.999` / `SNR_MIN_DB = 35.0` なので、変更前に撮ったゴールデンでも**通る**。
  ただし SNR の余裕は 3.7dB しかなく (8 分割の最悪セグメントは 32.4dB)、ローカルで撮り直して
  基準を引き直すのが望ましい。実機での試聴は別途要る。
- 差の相当部分は位相である。全セグメントで振幅スペクトル SNR が時間波形 SNR を上回り
  (平均 +7dB、最大 +18dB)、かつ時間とともに蓄積はしない (セグメント別 SNR は 32〜47dB で
  単調でない)。サンプル単位の SNR は f0 の微小変化に対して過敏な指標だと理解しておくこと。
- streaming 経路の遅延・レートロック・1 ブロックあたりの計算量は変わらない。フィルタは 66
  フレーム程度の配列に対する `np.median` 数回で、40ms の推論フロアに対して無視できる。
- `radius > 3` を選ぶと、現状の約 30ms の右文脈マージンを食い潰し、出力へ渡る末尾フレームが
  edge 複製に退化して実質未フィルタになる。壊れるのではなく効かなくなる方向の劣化であり、
  このマージンは右文脈 (lookahead) を増やせば広がる。
- `pitch_extract.py` から `scipy` の import が消える（このファイルでの唯一の用途だった）。
  scipy 自体は他所で使うため依存としては残る。
- 平滑化の経路が 1 本になったので、今後 f0 抽出器を追加しても平滑化を書き足す必要が無い。
- 有声区間の**先頭**フレームは依然として未保護である（左に窓が無いため edge 複製で恒等になる）。
  語頭に残るノイズ・ブレスの既知課題（[ADR-0059](0059-stream-vc-window-resolution-vad-gate.md)
  周辺）とは独立の話だが、語頭の f0 が 1 フレーム外れた場合はこのフィルタでは救えない。
