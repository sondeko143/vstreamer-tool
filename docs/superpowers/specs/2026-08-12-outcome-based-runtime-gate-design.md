# ランタイムの軽さを名前ではなく成果で守る

## 問題

ランタイムが重い依存を抱え込まないことを守っているのは、`tests/test_forbidden_imports.py` の `FORBIDDEN` というパッケージ名の列挙である。これは守りたいもの（起動が速く常駐が小さいこと）の代理でしかなく、**誰も名前を思いつかなかった依存は素通りする**。

さらに、名前ゲートは**根拠が消滅しても執行を続ける**。実測でその実例が出た。

- `transformers` を除外する理由として記録されているのは「uv.lock に載るだけで `uv audit` に 3 件の勧告が入る」だが、Python 3.14 のスクラッチプロジェクトに transformers 5.15.0 を入れて `uv audit` を回すと **「Found no known vulnerabilities」で終了コード 0**。この根拠は現時点で成立していない。
- `fairseq` は「requires-python を上げる際の障害」として記録されているが、**3.14 環境でも 0.12.2 が解決される**（28 パッケージ・18 インストール予定）。追加不能ではない。ただし torch 2.13.0 と torchaudio 2.11.0 を道連れにする。

理由は docstring の散文に埋まっており、**いつその根拠が切れるか**はどこにも書かれていない。だから切れても誰も気づかない。

宣言的に「解決の時点で止める」道は uv には無い。`[tool.uv] constraint-dependencies` に `torch<0` を置くと直接の `uv add torch` は終了コード 1 で失敗するが、**推移依存では禁止を報告せず古いバージョンへ後退する** — `uv add fairseq` は失敗せず、torch を要求しない fairseq 0.6.2 を選んで成功した。頼んだものと違うものが黙って入る。

## ゴール

- ランタイムの重さを、パッケージ名ではなく**観測可能な成果**で守る。
- 残す禁止エントリは、理由と**失効条件**を伴う宣言データとして 1 箇所に置く。
- 根拠が実測で成立しなくなったエントリが、気づかれないまま残り続けない。

## 非ゴール

- 起動時間をゲートにすること。実測でノイズが予算を超える（同一コードでテストスイートが 30.45s / 113.70s / 35.40s）。
- GPU や実行時資産（モデル・設定）を必要とする測定を通常のテスト実行に含めること。
- [ADR-0084](../../adr/0084-dependency-table-torch-gate.md) の依存表ガードの撤去。解決後の集合を検査する形は、上記のとおりこのエコシステムで唯一機能する。
- 新しい外部ツールの導入。
- `vspeech/` が特定モジュールを import しないという**構造**の制約のうち、重さと無関係なもの（実行プロバイダの単一ファクトリなど）の変更。

## 受入基準

- [ ] 通常のテスト実行で、ランタイムの起動が持ち込むモジュール集合と常駐メモリが検査される。GPU も実行時資産も必要としない。
- [ ] その検査は、名前を列挙していない新しい重い依存が入った場合にも失敗する。
- [ ] 検査が失敗したとき、メッセージが増えたモジュールを名指しする。
- [ ] 禁止エントリが、理由と失効条件を伴う宣言データとして 1 箇所にあり、テストはそれを読む。同じ内容が 2 箇所に書かれていない。
- [ ] 根拠が実測で成立しないエントリが残っていない。各エントリについて、残したか外したかとその判断の根拠が記録されている。
- [ ] 起動時間はゲートに使われていない。
- [ ] `torch` / `torchaudio` / `faiss-cpu` が依存表と解決済み集合の双方から排除されている状態が、引き続きテストで守られている。
- [ ] 変更の前後で、ランタイムのモジュール集合の大きさと常駐メモリの実測値が N とともに記録されている。
