# f0 の外れ値を有声区間単位で平滑化する (filter_radius 相当)

## 問題

f0 に中央値フィルタが掛かるのは harvest 経路だけで、既定の rmvpe と streaming の既定である
fcpe は抽出した生の f0 をそのまま合成器 (NSF) へ渡している。本家 RVC の `filter_radius` に
相当する平滑化が無い。

f0 抽出はブロックごとに独立で、ブロック間の連続性を拘束する仕組みも無い。そのため 1 フレーム
だけ現れるオクターブ誤りが何にも打ち消されずに合成へ届き、「キュッ」という短い異音として出力
に乗る。単発の外れ値は中央値フィルタが最も素直に消せる種類の誤りであり、品質の観点で現時点の
費用対効果が最も高い候補になっている。

一方で、素直に f0 列全体へ中央値フィルタを掛けると、無声を表す 0 が窓に混ざって有声区間の端が
0 側へ引かれる。有声の立ち上がりと切れ際が鈍るこの副作用は、消したい異音より耳につきやすい。

## ゴール

- 抽出器の種類によらず、有声区間の中に現れる単発の f0 外れ値が合成前に除去される。
- 平滑化の強さを運用者が設定で選べ、無効化もできる。
- 有声と無声の境界が平滑化によって鈍らない。
- 平滑化のために変換の遅延が増えない。
- 平滑化の経路が抽出器ごとに分かれていない。

## 非ゴール

- streaming VC の右文脈 (lookahead) を増やすこと。並行して独立に進行しており、この作業は
  自前の先読みを一切要求しない。
- オクターブジャンプの能動的な補正 (誤ったオクターブを倍・半へ引き戻す処理)。単発誤りより
  強い介入で、誤ったオクターブへロックし得るため独立に評価する。
- f0 抽出器そのものの変更、および既定の抽出器の変更。
- ブロックをまたいで f0 の状態を持ち越す連続性拘束。
- 語頭に残るノイズ・ブレスへの対策。
- バッチ経路と streaming 経路に異なる平滑化を与えること。

## 受入基準

- [ ] 有声区間の中に現れる単発の外れ値が、合成へ渡る前に周囲の値へ置き換わる。
- [ ] 無声フレームの値が平滑化の前後で変わらない。
- [ ] 有声区間の先頭と末尾のフレームが、隣接する無声フレームの影響で無声側へ引かれない。
- [ ] 平滑化の強さを設定で指定でき、無効化もできる。既定は有効。
- [ ] 平滑化を有効にしても、変換の片道遅延が増えない。
- [ ] 平滑化は抽出器の種類によらず同一の経路を通り、抽出器に固有の平滑化が残っていない。
- [ ] 既定の設定で harvest 経路が受ける平滑化の強さが、導入前と変わらない。
- [ ] 平滑化の強さを上げすぎたときに何が劣化するかが、設定例と決定記録から読み取れる。
- [ ] バッチ経路の数値ゴールデンが、既定の設定での新しい出力に対して更新されている。
- [ ] 既定の設定で、単発のオクターブ誤りに由来する異音が実機の試聴で確認できなくなる。
- [ ] 設定例と決定記録の記述が、実装と一致している。
