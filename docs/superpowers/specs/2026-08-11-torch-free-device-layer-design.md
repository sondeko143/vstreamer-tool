# デバイス解決層を torch 非依存にする

## 問題

GPU デバイスの解決 (`gpu_id` / `gpu_name` から実際のデバイスを決める処理) と、ONNX セッションを開くときの CUDA 実行プロバイダの可否判定が、どちらも torch の API を通っている。この 2 つが torch を全ワーカーに広げる結節点になっている。

音声認識 (whisper) の推論は ctranslate2 が行い、torch を必要としない。それにもかかわらず音声認識パイプラインは torch を読み込む。使っているのは解決結果のうち **デバイス番号ひとつだけ**で、デバイス名はログ出力にしか使われていない。

この整数 1 個の代償を実測した。

- torch の import だけで常駐メモリ **+476.7MB**、起動時間 **+3.17 秒** (torchaudio は追加 +3.2MB / +0.19 秒)。
- 稼働中の音声認識パイプライン (常駐 1343MB) の内訳では、ctranslate2 が使う CUDA 12 版 cuBLAS (145.8MB) と torch が持ち込む CUDA 13 版 cuBLAS (133.0MB) が**二重にロード**されている。さらに torch 由来のプロファイラ DLL が 87.1MB、torch 本体の DLL 群が 30.7MB を占める。

常駐パイプラインが複数あるため、この重複は台数分だけ効く。

加えて、現行の fp16 可否判定は GPU の**製品名の文字列**で行われている。名前に "16" を含むかどうかを見ているため、`NVIDIA A16` のように 16 を含む無関係な製品名や、VRAM 容量を名前に含むドライバ表記に対して fp16 を理由なく無効化する。判定したい性質はハードウェアの fp16 演算レートであり、製品名ではない。

## ゴール

- 音声認識パイプラインが torch を読み込まずに動作し、その分の常駐メモリと起動時間が削減される。
- デバイス解決と CUDA 実行プロバイダの可否判定が torch に依存しない。
- CUDA 実行プロバイダを要求するかどうかが、ONNX Runtime 自身が実際に提供できるかに基づいて決まる。
- fp16 可否がハードウェアの性質 (compute capability) から決まり、GPU の製品名の表記に左右されない。
- fp16 可否の判定が、GPU の無い環境でも自動テストで検証できる。
- 音声認識のみを利用するホストが、torch を導入せずに動作する。
- 音声変換 (RVC) の変換結果と設定の意味は変わらない。
- 依存パッケージを増やさない。
- torch がデバイス解決層に戻ってこないことが、自動テストで防がれる。

## 非ゴール

- 音声変換 (RVC) の変換経路そのものの torch 非依存化。今回は結節点のみを対象とし、変換経路は torch を使い続ける。
- torch を依存宣言・ロックファイルから完全に撤去すること。音声変換が使う限り残り、単一環境に全 extra を導入している構成では引き続き導入される。
- GPU 選択に関する設定項目の追加・変更・削除。`gpu_id` / `gpu_name` の意味と優先順位は現状維持。
- fp16 を使うかどうかを設定で切り替えられるようにすること。
- 音声認識のモデル・精度・演算精度の変更。
- ストリーミング VC のレイテンシやスループットの改善。
- 複数 GPU 間の負荷分散やデバイス自動選択の高度化。

## 受入基準

- 音声認識のみを有効にしたパイプラインのプロセスに、torch のモジュールがロードされていない。
- 同パイプラインの常駐メモリが、本変更前より 250MB 以上小さい。
- 同パイプラインの起動が、ワーカー開始のログ出力までの時間で本変更前より 2 秒以上短い。
- GPU 名による選択と GPU 番号による選択が、本変更の前後で同一のデバイスに解決される。解決されたデバイス番号とデバイス名は、従来どおりログに残る。
- CUDA デバイスが 1 台も見えない環境、および CUDA ドライバが存在しない環境で、起動が失敗せず CPU にフォールバックする。
- fp16 可否が compute capability から決まり、GPU の製品名に含まれる数字に影響されない。
- fp16 可否の判定が、実 GPU を持たない環境でも compute capability の境界値ごとに自動テストで検証される。
- ONNX セッションが CUDA 実行プロバイダを要求するかどうかが、実行時に利用可能な実行プロバイダの一覧に基づいて決まる。
- 音声変換 (RVC) の変換結果が、本変更の前後で既存の再現可能な基準出力と一致する。
- 音声変換とストリーミング VC が解決する fp16 可否の値が、本変更の前後で同一である。
- 音声認識に必要な依存だけを導入したホストで、音声認識パイプラインが起動し文字起こしできる。
- デバイス解決と ONNX セッション生成に関わるモジュールを読み込んでも torch がロードされないことが、汚染されない別プロセスでの自動テストで検証される。
- 依存パッケージが追加されない。
